## Why

当前内置 Gemma 3 1B IT int4 模型在模拟器 CPU 多轮会话中会把用户问题改写成礼貌反问，且首轮坏回答会被 Conversation 历史继续放大。现有运行时又没有记录每轮输入、原始模型消息、思考配置和生成结果，导致无法区分模型语义回声、通道解析错误与 UI 回显。

## What Changes

- 强化 Conversation 级系统指令，明确助手的离线文字问答能力、限制和“直接回答、不得复述或反问用户问题”的行为，同时继续原样发送用户当前轮次。
- 为内置小模型提供少量能力问答示例，并配置重复抑制，降低“您好，您好”和能力问题复述的概率。
- 在运行时检测高相似度语义回声；命中后丢弃受污染的原生 Conversation，使用不包含坏回答的干净会话最多重试一次，仍失败时明确返回质量错误而不展示伪回答。
- 增加仅调试构建启用的生成诊断日志，记录请求标识、模型/后端/采样/思考配置、消息角色与通道、首 Token、Token 统计、完成状态和脱敏后的输入输出证据。
- 增加截图所示单轮及 `hi` 后多轮回归，分别覆盖模拟器 CPU 与 Android 12+ ARM64 真机 GPU。

## Capabilities

### New Capabilities

- `chat-generation-observability`：定义端侧生成请求的安全调试日志、消息通道和完成指标，以便判断是否生成、是否启用显式思考以及为何触发质量回退。

### Modified Capabilities

- `multilingual-chat-policy`：将直接回答完整性从“非完全相等”提升为可检测的防语义回声契约，并规定坏回答不得污染后续会话。

## Impact

- 修改 `edge-ai` 的 Conversation 配置、生成事件处理、重复抑制、回声检测、干净会话重试及诊断数据。
- 修改 `app` 的生成失败呈现与诊断展示，并补充运行时、ViewModel 和设备测试。
- 不增加网络权限、云服务、手机控制能力或新的生产依赖；不重新引入当前用户轮次包装器。
- 保留现有模型文件、模型存储、GPU 到 CPU 回退和 LiteRT-LM JNI 串行生命周期。
